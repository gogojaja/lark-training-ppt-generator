# Skill: flowchart-skill

# 流程图快速生成技能包

> 版权：`../shared/references/COPYRIGHT.md`

## 1. 元数据

- **技能名称**：flowchart-skill
- **技能版本**：v1.2.0
- **发布日期**：2026-08-11
- **技能定位**：从 Word 文档提取业务流程，通过 CSV 节点表手工调整后，一键生成 PPT 流程图
- **适用场景**：业务流程图、操作手册流程图、制度流程图、培训流程图

## 2. 五步工作流

```
Word文档 → ①拆分 → ②选配色 → ③生成CSV → ④手工调整 → ⑤生成PPT
```

### Step 1：按章节拆分 Word 文档

**工具**：`tools/split_docx_by_level.py`（已有）

```bash
# 按一级标题拆分
py -3 tools/split_docx_by_level.py 输入文档/操作手册.docx 生成产物/拆分结果

# 按二级标题拆分
py -3 tools/split_docx_by_level.py 输入文档/操作手册.docx 生成产物/拆分结果 2
```

**最佳实践**：
- 优先按 Heading 1 拆分，每个章节独立处理
- 大文档（>50MB）先拆分再逐章提取流程
- 拆分后查看 `INDEX.md` 确认章节结构

### Step 2：确定配色方案

**预设配色**（`skills/flowchart-skill/presets/`）：

| 预设 | 主色 | 菱形 | 正常分支 | 异常分支 | 适用场景 |
|------|------|------|---------|---------|---------|
| `green` | 浅绿 C6EFCE | 浅黄 FFF2CC | 浅蓝 DDEBF7 | 浅红 FCE4EC | 合规/风控/审计 |
| `blue` | 浅蓝 D6E4F0 | 浅黄 FFF2CC | 浅绿 E2EFDA | 浅红 FCE4EC | 业务/运营/技术 |
| `red` | 浅红 FCE4EC | 浅黄 FFF2CC | 浅蓝 DDEBF7 | 淡红 F8D7DA | 应急/故障/升级 |
| `yellow` | 浅黄 FFF2CC | 浅蓝 DDEBF7 | 浅绿 E2EFDA | 浅红 FCE4EC | 培训/宣导/引导 |

**选择原则**：
- 主流程用柔和色（低饱和度），避免刺眼
- 菱形判断统一浅黄，保持一致性
- 异常分支用红色系，正常分支用蓝色/绿色系
- 标题栏用深色（深蓝/深绿），文字白色

### Step 3：生成流程节点 CSV 表

#### 方式 A · AI 语义化生成（推荐，主路径）

由 AI（skill 执行者）读取 Word 内容，按规范 schema 语义化输出最终 CSV。遵循项目「**模型无关 / 工具先于模型**」原则：语义判断由模型负责，机械排版/配色/坐标由脚本固化。

**工作流**：

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  ①文档预处理 │ →  │ ②AI语义提炼 │ →  │ ③质量校验   │ →  │ ④输出CSV    │
│  (拆分/提取) │    │  (生成节点) │    │  (自检清单) │    │  (全参数表) │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

**① 文档预处理**
- 大文档先按 Step 1 拆分为独立章节，每章单独生成流程图
- 可用 `tools/docx_to_flow_csv.py --json-only` 提取纯文本结构（辅助理解）
- 确定本章核心业务场景（一个场景 = 一个流程图）

**② AI 语义提炼（核心 Prompt 模板）**

> 请阅读以下业务文档章节，提炼为标准流程图节点 CSV。严格遵循以下规则：
>
> **一、基础规则**
> 1. 识别核心业务流程，严格按文档描述的执行顺序排列主流程节点
> 2. 每个节点精炼为**动词开头的动作句，控制在 8~15 字**（精简但不丢失业务语义，如"费用收取与短信通知"不要简化为"费用收取"）
> 3. 区分节点类型：**处理步骤**=矩形（rect）；**判断/条件**=菱形（diamond）
> 4. 主流程 seq 从 1 连续编号；分支节点 seq 从 41 开始，按出现顺序递增
> 5. 输出全参数 CSV 格式（含 config 区），使用 `green` 预设
> 6. 单入口单出口，整体从上到下流动
>
> **二、节点粒度（关键！避免合并过度）**
> 7. **判断节点不可合并**：文档中每个独立的校验/审核/判断动作（如"读取证件""人脸识别""介质校验""签名确认"）必须是独立的菱形判断节点，不得合并为一个"联网核查"类的笼统节点
> 8. **处理步骤谨慎合并**：只有两个连续步骤是同一动作的两个方面（如"读取并校验"）才合并；独立操作步骤（如"输入交易代码""选择介质类型""费用收取"）必须保留为独立节点
> 9. **交易入口不可缺**：如文档有"输入交易代码进入XX场景"，必须有对应节点（处理步骤）
> 10. **通知/打印类步骤不可省**：如"短信通知""凭证打印""回单服务"等辅助步骤，如文档明确列出则保留
>
> **三、分支识别（关键！避免分支遗漏）**
> 11. **每个判断节点必须有分支**：正常（`normal`）+ 异常（`error`），异常分支 branch_to 指向 41+ 分支节点
> 12. **异常分支必须有处理内容**：不能只写"异常处理"，要写具体处理动作（如"客户信息维护""上级现场审核""拒绝交易""重新签字"）
> 13. **分支识别关键词**：文档中出现"需…后才能办理""不通过则…""缺失时…""异常情况下…"等表述，对应一个异常分支节点
> 14. **分支编号规则**：按判断节点在主流程中的出现顺序分配分支号。第一个判断→分支41，第二个判断→分支42，依此类推。如果一个判断有多个分支，依次占用多个编号
>
> **四、质量校验（输出前必查）**
> 15. 输出后对照文档步骤序号逐一对齐，确保没有遗漏步骤
> 16. 确认每个菱形判断都有对应的异常分支和处理内容
> 17. 节点文字 8~15 字，既不冗长也不过度精简

**③ 质量自检清单（AI 输出后必查）**

**完整性检查**
- [ ] 主流程步骤是否完整覆盖业务关键动作（对照文档步骤序号逐一核对，无遗漏、无多余）
- [ ] 交易入口/起始步骤是否完整（如"输入交易代码""选择业务场景"等）
- [ ] 通知/打印/评价等辅助步骤是否保留（文档明确列出则不可省略）

**判断与分支检查**
- [ ] 每个独立校验动作是否都是独立的菱形判断节点（无合并过度）
- [ ] 每个菱形判断是否有"是/否"两个分支，branch_to 是否正确
- [ ] 异常分支是否都有明确的处理内容（非空泛的"异常处理"）
- [ ] 分支编号是否按判断出现顺序从 41 开始依次递增

**粒度与文字检查**
- [ ] 节点文字是否在 8~15 字之间（动词开头，精简但不丢失业务语义）
- [ ] 是否存在合并过度（将两个独立步骤合并为一个笼统节点）
- [ ] 是否存在拆分过度（同一动作的两个方面拆成两个节点）

**结构检查**
- [ ] seq 编号是否连续（主流程 1-N，分支 41+）
- [ ] 主流程顺序是否严格按文档描述的执行顺序（无顺序混乱）
- [ ] 配色是否符合预设规范（主流程绿/判断黄/正常分支蓝/异常分支红）
- [ ] 是否为单入口单出口结构

**④ 输出格式**：使用全参数 CSV 格式（含 config 全局配置区），参考 `templates/flowchart_full_config.csv`

#### 方式 B · 规则脚本离线草稿（备选，质量有限）

纯规则启发式，仅作快速了解文档结构和「AI 生成前的摸底」用。

#### 方式 C · 手工整理（AI 不可用时的替代）

按下方 schema 手工制表，或从方式 B 的草稿基础上修改。

**CSV 格式**（`skills/flowchart-skill/templates/flowchart_nodes.csv`）：

```csv
seq,node_type,content,shape,width_cm,height_cm,bg_color,text_color,branch_to,branch_label,branch_kind
1,main,客户到达网点取号,rect,5.0,0.6,C6EFCE,006100,,,
2,main,Pad身份识别与分流,rect,5.0,0.6,C6EFCE,006100,,,
3,main,选择证件类型并读取身份证件,diamond,4.5,1.0,FFF2CC,7F6000,41,缺失,error
41,branch,客户信息维护,rect,5.0,0.6,FCE4EC,C00000,,,
```

**字段说明**：

| 字段 | 必填 | 说明 |
|------|------|------|
| seq | Y | 序号（整数，主流程 1-N，分支 41+） |
| node_type | Y | `main`=主流程 / `branch`=分支节点 |
| content | Y | 节点文本内容 |
| shape | Y | `rect`=矩形 / `diamond`=菱形 / `circle`=圆形 / `round_rect`=圆角矩形 |
| width_cm | Y | 宽度（cm），矩形推荐 5.0，菱形推荐 4.5 |
| height_cm | Y | 高度（cm），矩形推荐 0.6，菱形推荐 1.0 |
| bg_color | Y | 背景色（6位 hex，不含 #） |
| text_color | Y | 字体颜色（6位 hex，不含 #） |
| branch_to | | 分支目标序号（主流程节点填写） |
| branch_label | | 分支标签（如"是"/"否"/"缺失"） |
| branch_kind | | `normal`=正常分支 / `error`=异常分支 |

**维度参考**（行业最佳实践）：

| 形状 | 推荐宽度 | 推荐高度 | 说明 |
|------|---------|---------|------|
| 矩形（rect） | 5.0cm | 0.6cm | 主流程步骤 |
| 菱形（diamond） | 4.5cm | 1.0cm | 判断/条件 |
| 圆形（circle） | 1.5cm | 1.5cm | 开始/结束 |
| 圆角矩形（round_rect） | 5.0cm | 0.6cm | 子流程 |

### Step 4：手工调整 CSV 表

**调整要点**：
1. **流程完整性**：检查是否有遗漏步骤或多余步骤
2. **分支逻辑**：确认每个菱形判断的"是/否"分支是否完整
3. **节点顺序**：seq 序号确保主流程连续（1,2,3...），分支用 41+ 编号
4. **文本精简**：每个节点控制在 15 字以内，避免框内文字溢出
5. **颜色一致性**：同类型节点使用相同配色

**常见调整**：
- 合并相似步骤（如"读取证件"+"校验证件"→"读取并校验证件"）
- 拆分复杂判断（一个菱形只对应一个二选一判断）
- 补充异常分支（每个菱形判断都应有异常路径）

### Step 5：生成 PPT 流程图

```bash
# 使用预设配色
py -3 生成脚本/csv_to_flowchart.py nodes.csv --preset green --out 流程图.pptx

# 自定义标题
py -3 生成脚本/csv_to_flowchart.py nodes.csv --preset blue --title "综合账户激活流程" --out 流程图.pptx

# 默认不生成连接线（如需连线显式加 --connectors）
py -3 生成脚本/csv_to_flowchart.py nodes.csv --preset green --connectors --out 流程图.pptx

# 仅输出 JSON（调试用）
py -3 生成脚本/csv_to_flowchart.py nodes.csv --json-only --out flow.json
```

## 4. 行业最佳实践

### 4.1 流程图设计规范

| 规范 | 说明 |
|------|------|
| 单一入口 | 流程图只有一个起点（开始节点） |
| 单一出口 | 流程图只有一个终点（结束节点），或明确的多出口标注 |
| 判断完整 | 每个菱形判断必须有"是"和"否"两个分支 |
| 从上到下 | 主流程从上到下流动，分支向右展开 |
| 文字精简 | 每个节点 8~15 字，避免长句（精简但不丢失业务语义） |
| 颜色一致 | 同类型节点使用相同配色，便于快速识别 |

### 4.2 节点粒度指导原则

> **核心原则**：宁拆不并。合并容易丢失关键判断和分支，拆分最多只是节点稍多。

| 场景 | 处理方式 | 示例 |
|------|---------|------|
| **两个独立校验动作** | ✅ 拆分为两个菱形 | "证件读取" + "人脸识别" → 两个独立判断，各有各的异常分支 |
| **同一动作的两个方面** | ⚠️ 可考虑合并 | "读取并校验证件" → 如果读取和校验是同一步骤的两个环节 |
| **交易入口/场景切换** | ✅ 必须独立节点 | "输入交易代码进入XX场景" → 独立处理节点（流程入口标志） |
| **通知/打印/回单** | ✅ 文档明确列出则保留 | "费用收取与短信通知" → 不要简化为"费用收取" |
| **选择 + 执行** | ✅ 拆分为两个节点 | "选择介质类型"（处理）+ "读取介质并校验"（判断） |
| **审核 + 审批** | ✅ 拆分为两个判断 | "柜员审核" + "主管审批" → 两个独立菱形，各自有分支 |
| **连续的纯处理步骤** | ⚠️ 可合并但不强制 | "打印凭证" + "打印回单" → 可合并为"凭证打印与回单服务" |
| **跨渠道/跨场景跳转** | ✅ 独立分支体现 | "异常后跳转柜面办理" → 作为异常分支节点体现 |

**判断标准**：
- 如果两个步骤**有各自独立的异常处理路径** → 必须拆分
- 如果两个步骤**使用不同的系统/设备/角色** → 必须拆分
- 如果两个步骤**在文档中分属不同的编号步骤** → 建议拆分
- 如果两个步骤**是同一个操作的瞬时连续动作** → 可考虑合并

### 4.3 常见节点类型

| 类型 | 形状 | 用途 | 颜色 |
|------|------|------|------|
| 开始 | 圆形 | 流程起点 | 深色 |
| 处理 | 矩形 | 操作步骤 | 浅绿/浅蓝 |
| 判断 | 菱形 | 条件分支 | 浅黄 |
| 正常分支 | 矩形 | 正常路径 | 浅蓝/浅绿 |
| 异常分支 | 矩形 | 异常路径 | 浅红 |
| 结束 | 圆形 | 流程终点 | 深色 |

### 4.4 质量检查清单

- [ ] 主流程步骤是否完整（无遗漏、无多余）
- [ ] 每个菱形判断是否有"是/否"两个分支
- [ ] 异常分支是否都有处理措施
- [ ] 节点文字是否精简（8~15字，不丢失业务语义）
- [ ] 配色是否一致（同类节点同色）
- [ ] 连线是否清晰（无交叉、无遗漏）
- [ ] 整体布局是否从上到下、从左到右

## 6. 故障排除

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 需要连接线 | 默认不绘制连线 | 使用 `--connectors` 或 CSV config `no_connectors=false` |
| 文字溢出框外 | 文本过长 | 精简节点文字至 15 字以内 |
| 颜色不一致 | CSV 颜色值错误 | 使用预设配色 `--preset green` |
| 菱形太小放不下文字 | 尺寸不合理 | 调整 width_cm=4.5, height_cm=1.0 |
| 分支节点位置偏移 | branch_to 序号错误 | 检查 seq 与 branch_to 对应关系 |
| AI生成节点过少 | 合并过度 | 参考 4.2 节点粒度指导原则，宁拆不并 |
| AI生成分支缺失 | 分支识别不足 | 检查文档中的「需…后办理」「不通过则」等关键词对应分支 |
