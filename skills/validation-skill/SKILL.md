# Skill: validation-skill

# 回读验证技能

## 1. 元数据

- **技能名称**：validation-skill
- **技能版本**：v1.0.0
- **发布日期**：2026-08-17
- **技能定位**：验证生成的PPT内容完整性、版面质量和设计规范
- **适用场景**：回读验证、内容完整性检查、设计质量验证
- **对应工作流**：SKILL.md Step 6（回读验证）

## 2. 工作流

```
生成PPTX → ①内容回读 → ②版面验证 → ③设计质量检查 → ④报告生成
```

### Step 1：内容回读

**回读内容**：
1. 提取所有幻灯片的文本内容
2. 对比源文档提取的内容
3. 检查是否有遗漏或错误

**验证规则**：
- 标题必须完整显示
- 正文内容无截断
- 关键数字/日期准确
- 特殊字符正确显示

### Step 2：版面验证

**验证内容**：
1. 幻灯片尺寸是否正确（16:9）
2. 内容是否超出幻灯片边界
3. 元素间距是否合理
4. 页码是否正确

**检查规则**：
- 内容边界检查（margin >= 500000 EMU）
- 垂直节奏检查（元素对齐）
- 重复元素检查（无重复内容）

### Step 3：设计质量检查

**检查内容**：
1. 配色方案是否统一
2. 字体字号是否规范
3. 图标显示是否正常
4. 对比度是否足够（WCAG AA）

**检查规则**：
- 配色一致性（主色/辅色/强调色）
- 字体规范性（中文：微软雅黑，英文：Calibri）
- 对比度 >= 4.5:1

### Step 4：报告生成

**报告格式**：
```json
{
  "slide_count": 15,
  "content_issues": [
    {"slide": 3, "type": "truncation", "detail": "标题被截断"}
  ],
  "layout_issues": [
    {"slide": 5, "type": "overflow", "detail": "内容超出右边界"}
  ],
  "design_issues": [
    {"slide": 7, "type": "contrast", "detail": "对比度不足 3.2:1"}
  ],
  "overall_score": 85,
  "pass": true
}
```

## 3. 生成脚本

```bash
# 完整验证
py -3 生成脚本/validate_ppt.py input.pptx --out validation_report.json

# 仅内容回读
py -3 生成脚本/validate_ppt.py input.pptx --mode content

# 仅版面检查
py -3 生成脚本/validate_ppt.py input.pptx --mode layout

# 仅设计检查
py -3 生成脚本/validate_ppt.py input.pptx --mode design
```

## 4. 验证标准

| 检查项 | 通过标准 | 严重程度 |
|--------|---------|---------|
| 内容完整性 | 无遗漏关键内容 | 高 |
| 文本截断 | 无文字被截断 | 高 |
| 边界溢出 | 内容不超出幻灯片 | 高 |
| 配色一致性 | 符合选定风格 | 中 |
| 字体规范 | 使用指定字体 | 中 |
| 对比度 | >= 4.5:1 | 中 |
| 页码正确 | 连续且准确 | 低 |

## 闭环执行系统

### 1. 任务入口
- **输入**：生成的PPTX文件、源文档（可选）
- **前置**：
  - PPTX文件已生成
  - Python 3.8+ 已安装
- **不适用**：
  - PPTX文件不存在或损坏
  - 源文档不可读

### 2. 执行状态
| 状态 | 进入条件 | 退出条件 | 处理方式 |
|------|---------|---------|---------|
| 待启动 | PPTX文件已准备 | 用户确认/系统启动 | 准备上下文与输入 |
| 执行中 | 任务已启动 | 关键动作完成或失败 | 按步骤执行 |
| 校验中 | 验证完成 | 通过/失败 | 生成报告 |
| 阻塞 | 依赖缺失 | 补充信息 | 暂停推进 |
| 完成 | 验证通过 | 进入交付 | 归档报告 |
| 回退 | 验证失败 | 回到生成步骤 | 修复问题 |

### 3. 执行动作层
- **执行步骤 1**：读取PPTX文件，提取文本内容
- **执行步骤 2**：检查版面布局
- **执行步骤 3**：检查设计规范
- **执行步骤 4**：生成验证报告
- **所需工具/脚本**：`validate_ppt.py`、python-pptx库
- **输入输出约束**：
  - 输入：PPTX文件路径
  - 输出：验证报告（JSON/Markdown）

### 4. 验收门禁
- **必须产出物**：验证报告
- **通过条件**：
  1. 无高严重程度问题
  2. 整体评分 >= 80
- **失败条件**：
  1. 存在高严重程度问题
  2. 整体评分 < 80
- **审核对象**：用户/系统

### 5. 失败处理
- **失败类型**：
  1. PPTX文件读取失败
  2. 文件格式损坏
- **恢复策略**：检查文件完整性，重新生成
- **回滚方案**：无（验证是只读操作）
- **重试策略**：修复PPTX后重试
- **是否需要人工确认**：验证失败时需要

### 6. 产出与交接
- **产出物列表**：验证报告
- **保存路径**：当前工作目录
- **交接对象**：用户/交付流程
- **下一步动作**：根据报告决定是否修复或交付
- **归档条件**：验证通过

### 7. 审计记录
- **执行时间**：记录开始和结束时间
- **关键参数**：PPTX路径、检查模式、问题数量
- **关键决策**：是否通过验证
- **结果证据**：验证报告路径
- **失败原因**：记录失败类型和详细信息
