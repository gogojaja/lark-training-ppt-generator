# 培训课程设计与宣讲 PPT 生成工作流

## 设计原则

本项目采用**本地优先、云端可选**的架构：
- 默认工作模式：在本地完成内容解析、整理、版式生成和交付产出
- 飞书协同：仅在需要导出、同步、发布时启用
- 若未安装 `lark-cli` 或未配置飞书环境，主流程仍可正常生成 PPTX / PDF / 其他本地产物

> **核心要求**：本地生成链路必须独立可用，不能因为缺失飞书平台能力而阻断主流程。

## 前置条件

仅支持 **user 身份**。执行前确保已授权：

```bash
# 读取文档 + 创建/编辑幻灯片
lark-cli auth login --domain docs,slides
# 若源文档在知识库，或需导入/上传素材，补充 drive 权限
lark-cli auth login --domain docs,slides,drive
```

## 工作流总览

```
{源文档 URL/token}
        │
        ▼
   Step 0: 需求澄清（受众/目标/页数/风格/品牌指南/导出格式）
        │
        ▼
   Step 1: 读取并解析源文档（docs +fetch）
        │
        ▼
   Step 2: AI 结构化提炼
   （密度策略 → 叙事重构 → 深度规范 → 分页 → 事实校验 → 大纲确认）
        │
        ▼
   Step 3: 风格样例预览与选择（2-3 变体 → 用户锁定视觉策略）
        │
        ▼
   Step 4: 规划层（品牌 VI 检测 → 写入 slide_plan.json）
        │
        ▼
   Step 5: 生成 XML 并创建幻灯片（截图复用 + AI 素材生成）
        │
        ▼
   Step 6: 回读验证（版面 + 内容完整性 + 修订 + 协作审阅）
        │
        ▼
   Step 7: 交付（演示文稿 + 备注 + 覆盖报告 + 配套物料 + 多格式导出）
```

## Step 0: 需求澄清（必做）

在读取文档前，先向用户确认以下要素，缺一不可：

| 要素 | 说明 | 默认值 |
|------|------|--------|
| 源文档 | 飞书文档 URL/token、知识库节点、或本地文件 | 必填 |
| 宣讲受众 | 全员 / 新员工 / 管理层 / 某业务线 | 必填 |
| 宣讲目标 | 是"知晓"（宣贯）、"会用"（操作培训）、还是"考核"（合规考点） | 宣贯 |
| 页数预期 | 宣讲时长 × 每页 2-3 分钟反推 | 15-20 页 |
| 视觉风格 | 公司 VI 配色 / 指定主题色 / 行业风格 | 依主题定 |
| 是否含操作截图 | 系统手册类建议保留关键操作截图 | 否 |
| 品牌指南 | 企业 VI 文档 URL/token（可选，用于品牌适配检测，详见 §4.0） | 无 |
| 导出格式 | 飞书演示 / PPTX / PDF / 多格式（详见 §7.4） | 飞书演示 |

> **关键判断**：宣讲目标决定信息密度策略——
> - **宣贯类**（知晓）：每页 1 个核心结论 + 3-5 个支撑点，细节下沉备注
> - **操作培训类**（会用）：每页必须保留完整操作说明，不得降级；详见 Step 2.3
> - **合规考点类**（考核）：突出红线、数字指标、违规后果

## Step 1: 读取并解析源文档

```bash
# 知识库文档先解析 wiki token
lark-cli wiki spaces get_node --as user --params '{"token":"<wiki_token>"}'
# 返回 obj_type / obj_token，用 obj_token 作为真实 doc token

# 读取全文结构（默认 simple scope 即可拿到标题层级）
lark-cli docs +fetch --doc "<doc_url_or_token>" --as user

# 长文档分段读取，避免单次输出过大
lark-cli docs +fetch --doc "<doc_url_or_token>" --scope simple --detail fragment
```

### 1.1 解析要点

1. 提取文档的标题层级（H1/H2/H3），作为 PPT 的分节依据
2. 识别文档类型：制度类（条款+罚则）、操作手册类（步骤+截图）、业务规范类（流程+角色）
3. 记录关键术语、数字指标、生效日期等强信息点
4. 文档中嵌入的 `<sheet>` / `<bitable>` / 画板，按 lark-doc 的下钻规则提取 token，必要时读取内部数据作为 PPT 图表素材

### 1.2 ⚠️ 文档完整性提取清单（操作手册类必做）

操作手册类文档必须完整提取以下内容，**不得遗漏任何章节**：

| 文档章节 | 提取要求 | PPT 对应 |
|----------|----------|----------|
| **场景说明** | 全文保留，包括场景定义、适用范围、渠道说明 | 独立页，不降级 |
| **业务办理流程** | 提取交易流程图（如有）+ 操作介绍全文 | 操作介绍独立页 + 职能流程图 |
| **操作介绍**（逐段） | 每段操作描述完整保留，不得压缩为要点 | 操作流程分步页 |
| **交易代码/权限** | 原文保留 | 流程总览页 |
| **操作步骤**（逐步） | 每步的操作说明、字段说明、注意事项全部提取 | 每步独立页或多步合并页 |
| **注意事项** | 原文逐条保留，不得合并或省略 | 每个操作步骤页必须含注意事项板块 |
| **特殊场景/红线** | 全文保留 | 独立页 |

> **禁止行为**：不得将操作手册的"操作介绍"章节压缩为 1-2 行摘要；不得将"注意事项"合并为通用提示；不得跳过任何操作步骤。

## Step 2: AI 结构化提炼（核心环节）

将源文档转化为**宣讲导向**的 PPT 大纲，不是文档目录的搬运。

### 2.1 信息密度策略（按宣讲目标分级）

| 宣讲目标 | 信息密度策略 | 细节处理 |
|----------|-------------|---------|
| **宣贯**（知晓） | 每页 1 个核心结论 + 3-5 个支撑点 | 详细条款下沉到备注或附件 |
| **操作培训**（会用） | **不降级**，每页保留完整操作说明 | 操作步骤、字段、注意事项全部保留在正文 |
| **合规考点**（考核） | 提炼考点 + 红线 + 数字指标 | 详细条款作为参考页附后 |

### 2.2 宣讲叙事重构

按宣讲目标重组结构，而非照搬文档顺序：

- **宣贯类**：背景与目的 → 核心条款 → 适用范围 → 权责划分 → 违规处理 → Q&A
- **操作培训类**：业务场景导入 → 角色与入口 → 关键操作流程（分步截图）→ 常见问题 → 练习/考核
- **合规考点类**：制度要点 → 典型案例 → 红线清单 → 自测题

### 2.3 ⚠️ 操作培训类 PPT 内容深度规范（核心）

当宣讲目标为"操作培训"（会用）时，**必须遵守以下规范**：

#### 2.3.1 必须包含的页面类型

| 页面类型 | 说明 | 是否必须 |
|----------|------|---------|
| **场景说明页** | 完整保留源文档的"场景说明"章节，包括场景定义、适用范围、渠道对比 | ✅ 必须 |
| **操作介绍页** | 完整保留源文档的"操作介绍"章节，按步骤展开 | ✅ 必须 |
| **职能流程图页** | 基于操作介绍重画泳道图，不同角色/系统用不同颜色 | ✅ 必须 |
| **柜面操作总览页** | 交易代码、权限、步骤总览 | ✅ 必须 |
| **分步操作页** | 每个操作步骤独立成页（或相邻步骤合并），含四要素 | ✅ 必须 |
| **特殊场景/红线页** | 完整保留特殊场景和注意事项 | ✅ 必须 |

#### 2.3.2 分步操作页四要素（每个操作步骤页必须包含）

```
┌─────────────────────────────────────────┐
│  步骤标题（如"步骤3：选择开户介质"）        │
├─────────────────────────────────────────┤
│  ① 操作说明                              │
│     - 完整的操作描述，保留原文关键字段      │
│     - 如有子步骤（如6种介质），逐项列出     │
│                                         │
│  ② 关键字段/操作要点                      │
│     - 每种介质需填写的字段清单             │
│     - 关键操作按钮、界面路径               │
│                                         │
│  ③ ⚠️ 注意事项（橙色高亮板块）            │
│     - 原文注意事项逐条保留                │
│     - 不得合并、省略、改写                 │
│                                         │
│  ④ 易错点提示（可选但推荐）               │
│     - 高频错误、常见问题                  │
└─────────────────────────────────────────┘
```

#### 2.3.3 职能流程图规范

- **必须用泳道图**，按角色分行（如：客户 / 厅堂人员 / 柜员 / 系统 / 授权人员）
- **不同角色用不同颜色区分**，并附图例
- **条件分支节点用椭圆形**，常规操作用圆角矩形
- 若源文档流程图不清晰或缺失，**基于操作介绍文本重新绘制**
- 跨泳道的交互用箭头连接，体现职责交接

#### 2.3.4 注意事项呈现规范

- 每个操作步骤页底部必须有橙色"注意事项"板块
- 注意事项内容从源文档原文逐条提取，不得省略
- 若某步骤在源文档中无明确注意事项，可标注"本步骤无特殊注意事项"或补充常见易错点
- 特殊场景（代理办理、老年客群、未成年人、大额存取等）单独成页，集中展示注意事项

### 2.4 受众适配

- 新员工：增加背景铺垫、术语解释、操作截图；操作步骤更详细
- 管理层：突出权责、KPI 影响、风险点，弱化操作细节
- 全员宣贯：突出"对我有什么影响""我该做什么"

### 2.5 大纲输出格式

交给用户确认时使用：

```text
[宣讲 PPT 标题] — [定位描述]，面向 [受众]，目标：[宣贯/培训/考核]

页面结构（N 页）：
1. 封面页：[标题] | [副标题/宣讲场景]
2. 目录页：[分节列表]
3. 场景说明：[场景定义] | [适用范围] | [渠道对比]
4. 操作介绍：[完整业务流程概述]
5. 职能流程图：[角色分工泳道图]
6. 柜面操作总览：[交易代码] | [权限] | [步骤总览]
7. 步骤1-2：[操作说明] | [关键字段] | [注意事项]
8. 步骤3：[6种介质操作] | [字段清单] | [注意事项]
...
N. 结尾页：[行动指引 / 速查表 / Q&A]

风格：[配色方案]，[排版风格]
内容深度：[每页四要素覆盖情况]
注意事项覆盖：[列出每个步骤的注意事项来源]

事实校验批注：
- [信息点1]: [置信度] [校验结果]
- [信息点2]: [置信度] [校验结果]
（无关键信息点时标注"本次大纲无需联网校验"）
```

> **必须等用户确认大纲后再进入 Step 3（风格样例预览）**，避免做完发现方向偏差。

### 2.6 布局模板参考库

每种页面类型提供 2-3 种布局模板，在大纲阶段标注每页的推荐布局，供 Step 3 风格样例预览时复用：

| 页面类型 | 布局模板选项 | 信息密度特征 | 适用场景 |
|----------|-------------|-------------|---------|
| **分步操作页** | 双栏型（左文右图） | 文本量中等，截图/卡片占 35-45% 宽度 | 单步无子项或 1-2 种子介质 |
| | 三栏型（上说明 + 中字段卡 + 下注意事项） | 文本量高，纵向分层 | 四要素齐全的独立步骤 |
| | 卡片矩阵型（2×3 或 3×2 卡片） | 子项多，每卡片独立展示 | 6 种介质、多种选项并列 |
| **场景说明页** | 定义+类型双卡型 | 内容简洁，左右对比 | 场景定义明确、类型少 |
| | 通栏+要点条型 | 要点多，逐条展开 | 核心要点 ≥4 条 |
| **流程图页** | 横向泳道型 | 角色 ≤5，步骤清晰 | 常规角色分工展示 |
| | 纵向泳道型 | 角色 >5 或步骤纵向延伸 | 角色多、流程长 |
| | 紧凑流程型 | 角色少、步骤少 | 简化展示，节约空间 |
| **速查表页** | 表格型 | 字段多，结构化对比 | 7 步以上操作流程速查 |
| | 卡片型 | 步骤少，每步突出 | 3-5 步核心流程 |
| | 时间线型 | 步骤有明确先后依赖 | 流程强调时序 |

### 2.7 动态分页策略

分步操作页的分页判定规则（在生成时自动应用）：

| 判定条件 | 分页策略 |
|----------|---------|
| 单步操作说明 ≤3 行 + 无子项 | 可与相邻步骤合并为一页 |
| 单步含子选项（如 6 种介质） | 拆分为多页，每页 2-3 个子项 |
| 单步注意事项 ≥4 条 | 注意事项独立成页 |
| 四要素总文本量 > 页面预估容量（正文区高度的 80%） | 自动拆分为"操作页 + 注意事项页" |
| 介质/选项数 > 4 且每种需展示字段清单 | 使用卡片矩阵布局，按 2×2 或 3×2 分页 |

> 分页决策写入 `slide_plan.json` 的 `pagination_plan` 字段，作为生成依据。

### 2.8 事实校验（联网搜索增强）

在生成大纲后、提交用户确认前（§2.9），对结构化提炼过程中提取的**关键信息点**进行联网交叉验证，降低信息错误风险。

#### 2.8.1 校验范围与触发条件

| 信息类型 | 校验内容 | 是否必须触发 | 降级策略（搜索失败时） |
|----------|---------|-------------|---------------------|
| **数字指标** | 金额上限、比例、数量阈值 | 中/低置信度必须触发 | 标注"⚠️ 联网校验未完成，置信度维持原判" |
| **生效日期** | 制度生效日、废止日、过渡期 | 低置信度必须触发 | 同上 |
| **法规引用** | 引用的法律法规、监管文件 | 任何置信度必须触发 | 标注"⚠️ 请人工核实法规有效性" |
| **机构名称/术语** | 部门名称、系统名称、业务术语 | 可选触发 | 跳过，不阻塞流程 |
| **市场数据** | 行业排名、市场份额、增长率 | 可选触发 | 跳过，不阻塞流程 |

#### 2.8.2 校验流程

```
提取关键信息点 → 标记置信度（高/中/低）
        │
        ├─ 高置信度（源文档明确标注+数字精确）→ 直接通过
        │
        ├─ 中置信度（源文档提及但未标注出处）→ 联网搜索核实
        │
        └─ 低置信度（模糊表述、可能过时）→ 联网搜索 + 标注待确认
```

#### 2.8.3 校验输出

将校验结果以批注形式附加到大纲输出中（填入 §2.5 模板的"事实校验批注"区域）：

```text
[信息点] 季度考核奖金上限为 50 万元
[置信度] 中
[校验结果] ✅ 已核实 — 来源：《2025 年度绩效考核办法》第 12 条

[信息点] 新客户开户年龄限制为 16 周岁
[置信度] 低
[校验结果] ⚠️ 待确认 — 源文档未标注生效日期，建议核实最新监管要求
```

#### 2.8.4 事实校验与源文档保真的仲裁规则

当联网发现源文档信息过时时，按以下规则处理，不改变源文档原文：

| 场景 | 仲裁规则 | 批注标注 |
|------|---------|---------|
| **源文档为内部制度** | 以源文档为准 | "外部数据已更新，源文档待修订" |
| **源文档引用外部法规** | 以联网最新数据为准 | "法规已更新，建议同步修订源文档" |
| **无法判定** | 保留源文档原文 | "⚠️ 待确认"，由用户在确认环节决策 |

> **原则**：校验不改变源文档原文，仅在大纲中附加置信度批注；用户确认环节可针对"待确认"项做出决策。

### 2.9 大纲提交用户确认

事实校验完成后，将含批注的大纲提交用户确认。用户确认后进入 Step 3（风格样例预览）。

> 用户可针对"⚠️ 待确认"项做出决策：采纳源文档原文 / 采纳联网最新数据 / 标注后暂不处理。

## Step 3: 风格样例预览与选择

**位置**：大纲确认后（§2.9）、规划层写入前（Step 4）。

**目的**：避免全量生成后才发现风格不符导致整份返工。用户在大纲阶段对视觉风格只有文字描述，本环节通过生成 1-2 个代表性页面的多风格样例，让用户实际看到效果后再锁定视觉策略。

### 3.1 样例页选取原则

选取 **信息密度最高、布局最复杂** 的页面类型生成样例，确保该页面能通过后，其余页面布局更宽松：

| 文档类型 | 推荐样例页类型 | 理由 |
|----------|--------------|------|
| 操作手册类 | 分步操作页（含四要素） | 信息密度最高，布局最难，代表性强 |
| 制度类 | 核心条款页 + 红线清单页 | 条款层级多，需验证排版清晰度 |
| 合规考点类 | 考点提炼页 + 自测题页 | 需要验证信息密度和交互元素呈现 |

### 3.2 风格变体生成规则

针对选取的样例页，生成 **2-3 种风格变体**。每个变体必须包含：

1. **配色方案**（从 Color Selection Matrix 中选取，与行业/主题匹配）
2. **布局模板**（从 §2.6 布局模板库中选取）
3. **注意事项呈现方式**（底部通栏 / 右侧固定侧栏 / 折叠卡片式）
4. **对比度合规校验**（配色方案生成后自动计算 WCAG AA 对比度，正文文本与背景对比度 ≥ 4.5:1，大标题 ≥ 3:1；不合格时自动推荐替代色值）

**变体组合示例**（以操作手册类为例）：

| 变体 | 配色 | 布局 | 注意事项呈现 | 适用偏好 |
|------|------|------|-------------|---------|
| A | Ocean Gradient（蓝青系，清晰专业） | 三栏型（上说明 + 中字段卡 + 下注意事项） | 底部通栏橙色高亮 | 追求清晰、信息密度高 |
| B | Charcoal Minimal（深灰系，沉稳） | 双栏型（左文右图） | 右侧固定侧栏 | 追求简洁、留白多 |
| C | Warm Terracotta（暖色系，亲和） | 卡片矩阵型 | 折叠卡片式 | 追求亲和、适合全员宣贯 |

### 3.3 样例页生成方式

```bash
# 生成步骤（脚本可按以下逻辑实现）：
# 1. 从已确认的大纲中提取 1 页最具代表性的内容
# 2. 按风格变体参数（配色/布局/注意事项呈现）生成 2-3 页样例 PPTX
# 3. 输出到临时目录，交付用户等待选择反馈

# 方式B：飞书 slides 创建（如需要在线预览）
lark-cli slides +create --as user --title "[样例预览] 综合个人开户 · 风格对比"
```

### 3.4 用户选择后锁定视觉策略

用户确认风格变体后，将以下信息写入规划层文件，后续全量生成严格遵循：

```json
{
  "visual_strategy": {
    "selected_variant": "A",
    "color_palette": {
      "primary": "065A82",
      "secondary": "1C7293",
      "accent": "E86A33",
      "bg": "F5F7FA"
    },
    "layout_template": "three_column",
    "notice_style": "bottom_banner",
    "motif": "step_number_circle",
    "font_heading": "Microsoft YaHei",
    "font_body": "Microsoft YaHei"
  }
}
```

> **锁定后禁止中途更换配色或布局风格**，如需调整，按 §6.3 迭代修订机制处理。

## Step 4: 规划层 — 写入 slide_plan.json

用户确认大纲后，按 lark-slides 的 planning-layer 规则，创建目录并写入规划文件：

```bash
mkdir -p .lark-slides/plan/<deck-or-task-id>
```

### 4.0 品牌适配与企业 VI 检测

在写入规划层前，若用户在 Step 0 提供了企业品牌指南（Brand Guidelines）或现有母版文件，必须先执行品牌检测：

```bash
# 1. 读取品牌指南文件（飞书文档或本地文件）
lark-cli docs +fetch --doc "<brand_guideline_url>" --as user

# 2. 自动提取 VI 关键字段（可按以下逻辑实现脚本）
#    扫描文档中的 HEX 色值、字体声明、Logo 位置说明，结构化输出为 JSON
```

**提取的 VI 字段**：

| 字段 | 说明 | 示例 |
|------|------|------|
| `primary_color` | 企业主色（HEX） | `#0052D9` |
| `secondary_color` | 企业辅色（HEX） | `#00B96B` |
| `accent_color` | 强调色（HEX） | `#FF7D00` |
| `font_heading` | 标题字体 | `PingFang SC` |
| `font_body` | 正文字体 | `Microsoft YaHei` |
| `logo_placement` | Logo 默认位置 | `右上角 / 左上角 / 底部居中` |
| `logo_file_token` | Logo 素材 token | 从 drive 获取 |
| `slide_master_id` | 母版 ID（如有） | `master_001` |

**品牌冲突判定**（使用 CIE Delta E 色差公式）：

| ΔE 范围 | 判定 | 处理方式 |
|---------|------|---------|
| ΔE < 15 | 近似色，可兼容 | 直接使用 Step 3 选定方案 |
| 15 ≤ ΔE ≤ 30 | 需人工确认 | 向用户展示对比，由用户决策 |
| ΔE > 30 | 冲突 | 优先遵循品牌指南，重新生成风格样例 |

**异常降级**：若品牌指南无法访问（文档权限不足/链接失效），使用 Step 3 风格样例选定方案，并向用户提示"品牌指南读取失败，使用已选定风格方案"。

若用户未提供品牌指南，直接使用 Step 3 选定的风格方案。

`slide_plan.json` 必须包含：
- **deck 级品牌策略**（来自 §4.0 检测）：`brand_strategy` 对象，含 `vi_source`、`primary_color`、`font_heading`、`font_body`、`logo_placement`、`logo_file_token`
- **deck 级视觉策略**（来自 Step 3 锁定）：`visual_strategy` 对象，含 `selected_variant`、`color_palette`、`layout_template`、`notice_style`、`motif`、`font_heading`、`font_body`
- **deck 级分页策略**（来自 §2.7 动态分页）：`pagination_plan` 对象，列出每页的分页决策（合并/拆分/独立）及理由
- **逐页 plan**：每页含
  - `key_message`（主结论）
  - `layout_type`（几何布局）
  - `layout_template`（§2.6 布局模板库中选取的具体模板名，如 `three_column`、`card_matrix_2x3`）
  - `visual_focus`（主视觉）
  - `text_density`（文本量：low / medium / high）
  - `asset_need`（含 `fallback_if_missing`）
  - `notice_style`（该页注意事项呈现方式，覆盖 deck 级默认值）
- **⚠️ 操作培训类额外字段**：每页 plan 须含 `content_elements`（四要素覆盖情况）和 `notice_items`（注意事项来源段落）

### 操作手册类 PPT 视觉建议

- 配色偏向清晰（蓝/青主色 + 绿/橙状态色）
- motif 可用"步骤编号圆环""系统界面卡片框"
- 操作步骤页用"左文右图"双栏，截图占 35-45% 宽度
- **关键路径用职能泳道流程图**（必须，非可选）
- **注意事项用统一的橙色高亮板块**（全 deck 一致）

### 制度类 PPT 视觉建议

- 配色偏向沉稳（深蓝/墨绿/深灰主色 + 金/橙强调色），传递权威感
- motif 可用"条款编号节点""章节侧边栏""印章/徽章元素"
- 权责划分页用组织架构图，流程页用流程图，红线清单用对比列

## Step 5: 生成 XML 并创建幻灯片

### 5.1 创建方式选择

| 场景 | 推荐方式 |
|------|----------|
| 简单 XML（1-3 页、结构简单、几乎无复杂中文） | `slides +create --slides '[...]'` 一步创建 |
| 复杂 XML（多页、含中文、大段文本、复杂布局） | **两步创建**：先 `slides +create` 创建空白 PPT，再逐页 `xml_presentation.slide.create` |
| 超过 10 页 | 必须两步创建 |

### 5.2 创建空白 PPT

```bash
lark-cli slides +create --as user --title "<宣讲标题>"
# 记录返回的 xml_presentation_id
```

### 5.3 逐页添加（复杂内容推荐）

```bash
# 查看参数结构（每次必做）
lark-cli schema slides.xml_presentation.slide.create

# 用 jq 模板避免转义问题
lark-cli slides xml_presentation.slide create \
  --as user \
  --params '{"xml_presentation_id":"<YOUR_ID>"}' \
  --data "$(jq -n --arg content '<slide xmlns="http://www.larkoffice.com/sml/2.0">
  <style><fill><fillColor color="BACKGROUND_COLOR"/></fill></style>
  <data>
    <!-- shape / content / table / chart / whiteboard 等元素 -->
  </data>
</slide>' '{slide:{content:$content}}')"
```

### 5.4 素材处理（截图复用 + AI 智能生成）

#### 5.4.1 操作截图复用（系统手册类）

若源文档含系统操作截图，需要复用到 PPT：

```bash
# 1. 从源文档下载图片素材
lark-cli docs +media-download --doc "<doc_url_or_token>" --as user --output-dir .lark-slides/assets/

# 2. 上传到目标演示文稿，获取 file_token
lark-cli slides +media-upload --as user --presentation "<xml_presentation_id>" --file .lark-slides/assets/screenshot_01.png

# 3. 用返回的 file_token 写入 <img src="file_token">
```

#### 5.4.2 AI 智能素材生成

当页面需要配图但无真实截图可用时，根据 `asset_need.fallback_if_missing` 的描述生成 AI 素材。

**AI 素材生成触发条件**：

| 页面类型 | 默认是否生成配图 | 触发逻辑 |
|----------|----------------|---------|
| 封面页 | 是 | 自动生成与主题匹配的场景配图 |
| 场景说明页 | 是 | 若源文档无截图，自动生成场景插画 |
| 分步操作页 | 否 | 仅当 `asset_need.fallback_if_missing` 标注为 `ai_generate` 时触发 |
| 流程图页 | 否 | 使用 XML-native shape，不触发 AI 生成 |
| 数据统计页 | 是 | 含 ≥3 个数字指标时自动生成数据图表 |
| 其他页 | 否 | 需用户在 Step 0 或修订环节明确指定 |

| 素材类型 | 生成方式 | 输出格式 |
|----------|---------|---------|
| **场景配图** | 根据场景描述生成场景化插画 | PNG 1200×675 |
| **图标组** | 生成统一风格的步骤图标（编号+图形） | SVG 或 PNG |
| **数据图表** | 根据数字生成柱状图/饼图/趋势图 | 内嵌 XML chart |
| **流程图节点** | 生成圆角矩形、菱形判断节点等装饰元素 | XML shape |

**AI 素材生成规范**：
- 风格必须与 `visual_strategy` 锁定的配色方案一致
- 图标使用统一线宽（2px）和圆角（4px）
- 场景配图避免生成真实人物面部，使用抽象化/剪影风格
- 所有 AI 生成素材需在 `slide_plan.json` 的 `asset_need` 中标注 `generated_by_ai: true`

**异常降级**：若 AI 生成失败或风格不符，回退到 XML-native shape 兜底，向用户提示"AI 配图生成失败，已用图形化元素替代"，绝不留空白图片框。

### 5.5 ⚠️ 操作培训类内容深度检查（生成时自检）

每生成一个操作步骤页后，自检以下四要素是否齐全：

- [ ] **操作说明** — 是否完整保留了源文档的操作描述？
- [ ] **关键字段** — 是否列出了该步骤涉及的所有字段/选项？
- [ ] **注意事项** — 是否从源文档提取了对应的注意事项原文？
- [ ] **易错点** — 是否补充了常见易错提示？

> 若任何一项缺失，不得进入下一页生成，先补齐内容。

- [ ] 页数与大纲一致

**内容覆盖度检查**：
- [ ] **场景说明** — 源文档的"场景说明"章节是否完整呈现？（场景定义 + 全部渠道说明）
- [ ] **操作介绍** — 源文档的"操作介绍"章节是否完整呈现？（每段操作描述对应到 PPT 页面）

- [ ] **介质/选项完整** — 每个步骤的可选项（如6种介质）是否全部列出？
- [ ] **字段清单完整** — 每种介质的填写字段是否完整列出？

- [ ] **特殊场景完整** — 代理办理、老年客群、未成年人、大额存取等特殊场景是否独立成页？

局部问题优先用 `+replace-slide`（block_replace / block_insert）修正，不要整页重建。

### 6.3 迭代修订机制

交付后用户提出修改请求时，按以下流程处理，避免整份重建。

#### 6.3.1 修订请求格式（支持自然语言）

用户可以用**自然语言**直接表达修改意图，AI 自动解析并映射到结构化操作：

**自然语言输入示例**：
- "第 5 页的配色换成深灰系，看起来太亮了"
- "步骤 3 的注意事项补充一条：大额存取需提前一天预约"
- "把封面的标题字号调大两号"
- "P7-P9 合并成一页，内容太少了"

**AI 解析输出**：

```json
{
  "intent_parsed": {
    "pages": ["P5"],
    "modification_type": "配色",
    "description": "将配色从当前方案更换为深灰系",
    "reason": "用户反馈当前配色太亮"
  },
  "priority_auto_assigned": "P2",
  "estimated_scope": "仅 P5 配色更换 + 相邻页检查"
}
```

**结构化请求（仍支持）**：

```
修订请求：
- 页码/范围：[具体页码，如 "P7" 或 "P3-P5"]
- 修改类型：内容 / 布局 / 配色 / 字号 / 其他
- 修改描述：[具体说明]
- 修改原因：[为什么需要改]
```

> **提示**：自然语言请求中若包含模糊表述（如"好看一点"），AI 需向用户确认具体偏好（配色方向/留白多少/字体粗细），避免无目标反复微调。

#### 6.3.2 修订优先级与处理策略

| 优先级 | 判定条件 | 处理策略 | 验证范围 |
|--------|---------|---------|---------|
| **P0 — 紧急** | 文字溢出、重叠、边界问题；内容缺失导致信息不完整 | 立即修正，使用 `+replace-slide` 局部替换受影响页面 | 仅验证修改页面 |
| **P1 — 重要** | 内容补充（新增注意事项、修正字段描述）；布局调整（卡片大小、间距） | 修正后补齐内容，重新运行该页面的 validate_layout.py | 修改页面 + 相邻页面（布局调整可能影响周边） |
| **P2 — 建议** | 风格微调（配色深浅、字号大小、图标样式）；备注层补充 | 批量收集后统一处理，避免频繁打断 | 全 deck 验证（配色/字号改动影响全局） |

**自然语言请求的优先级自动判定规则**：
- 含"溢出""重叠""缺失""缺字""错字" → 自动判为 P0
- 含"补充""新增""修改""调整大小" → 自动判为 P1
- 含"调一下""好看一点""换个风格" → 自动判为 P2，需用户确认后再执行

#### 6.3.3 修订流程

```
用户提交修订请求（自然语言或结构化）
       │
       ▼
  AI 解析意图 → 自动判定优先级（P0 / P1 / P2）
       │
       ├─ P0 → 立即修正 → 局部验证 → 交付
       │
       ├─ P1 → 修正 + 相邻页检查 → 局部验证 → 交付
       │
       └─ P2 → 收集多个 P2 后统一处理 → 全量验证 → 交付
```

#### 6.3.4 禁止行为

- **禁止在锁定视觉策略后中途更换整体配色或布局风格**（如用户坚持更换，视为新需求，需退回 Step 3 重新生成样例）
- **禁止仅因"看起来不够好看"进行无目标的反复微调**（每次修订必须有明确的修改类型和原因）
- **禁止跳过验证直接交付**（任何修改必须通过对应优先级的验证范围）

### 6.4 协作审阅与多人批注

交付后支持多人在线审阅，收集批注后按优先级归类处理。

**单人修订与多人审阅的切换条件**：
- 用户单人直接提修改 → 走 §6.3 单人修订流程
- 用户主动发起团队审阅（如"让XX也看看""发给团队审阅"）→ 走 §6.4 多人审阅流程
- 两者最终统一进入 P0/P1/P2 修订执行

#### 6.4.1 审阅流程

```
生成审阅链接 → 分享给团队成员 → 收集批注
        │
        ▼
  批注自动归类（P0 / P1 / P2）
        │
        ├─ P0 批注 → 立即修正 → 局部验证 → 通知批注人
        │
        ├─ P1 批注 → 汇总后统一修正 → 局部验证 → 通知批注人
        │
        └─ P2 批注 → 与所有者确认后批量处理 → 全量验证
```

#### 6.4.2 批注来源与处理

| 批注来源 | 典型内容 | 自动归类 |
|----------|---------|---------|
| **内容审阅人**（业务专家） | 字段描述错误、遗漏注意事项 | P0 / P1 |
| **视觉审阅人**（设计师） | 配色偏差、字体不统一、间距问题 | P1 / P2 |
| **宣讲人**（最终使用者） | 备注层补充、讲解节奏调整 | P2 |

#### 6.4.3 批注冲突处理

当多个审阅人对同一页提出冲突批注时：
1. 内容类冲突（如字段描述矛盾）→ 以业务专家批注为准，标注来源
2. 视觉类冲突（如配色偏好不同）→ 汇总后由所有者（宣讲负责人）决策
3. 优先级冲突（如同一页既有 P0 又有 P2）→ 先处理 P0，P2 纳入后续优化

> **效率原则**：多人审阅时，优先处理 P0 批注，P1 批注在 24 小时内汇总处理，P2 批注在下次版本迭代时统一处理。

## Step 7: 交付

验证通过后，向用户交付**主交付物 + 配套物料包**。

### 7.1 主交付物

1. **演示文稿链接**：从 `xml_presentations.get` 返回中提取 URL，或告知用户在飞书云空间查找
2. **宣讲备注**：每页按模板自动生成演讲者备注（对应 slide 的 `<note>` 元素），详见 §7.2
3. **内容覆盖报告**：列出源文档各章节在 PPT 中的对应页面，证明无遗漏

### 7.2 备注层自动生成规范

每页 PPT 的 `<note>` 元素按页面类型自动生成，作为宣讲人的讲稿参考：

| 页面类型 | 备注内容模板 | 生成规则 |
|----------|-------------|---------|
| **封面页** | 宣讲开场白（30-60 秒） | 标题 + 受众 + 目标 + 时长提醒 |
| **目录页** | 章节过渡语 | 每节的 1 句话导入语，串联逻辑 |
| **场景说明页** | 背景故事 + 实际案例引入 | 补充一个与受众相关的真实场景描述 |
| **分步操作页** | 讲解节奏建议 + 易混淆点口头提醒 + 互动提问 | 操作说明中的关键动词标红提醒；列出 1-2 个现场互动问题 |
| **注意事项页** | 合规风险强调语 + 真实违规案例摘要 | 每条注意事项对应一句"如果不遵守会怎样"的后果描述 |
| **流程图页** | 角色交接要点 + 跨部门协作提醒 | 每个跨泳道箭头对应一句交接说明 |
| **特殊场景页** | 红线强调语 + 处理话术建议 | 每种特殊场景给出标准处理话术 |
| **速查表页** | 复习提问 + 自测题（3-5 题） | 从速查表中抽取关键数字和字段作为考题 |
| **结尾页** | 行动号召 + 后续支持说明 | 明确受众下一步该做什么、遇到问题找谁 |

**备注生成方式**：

```bash
# 方式A：生成时同步写入（推荐）
# 在生成每页 XML 时，同步填充 <note> 元素
<slide>
  <note>
    <textBody>
      <p>【讲解节奏】本页重点讲 X，建议用时 2 分钟...</p>
      <p>【易混淆点】注意区分 A 和 B...</p>
      <p>【互动提问】大家可以思考一下，如果遇到 C 情况该怎么办？</p>
    </textBody>
  </note>
  ...
</slide>

# 方式B：生成后批量补充
# 导出所有页面文本，按模板批量生成备注，再回写
```

> 备注层仅对宣讲人可见，内容应比正文更丰富（补充背景、案例、话术），但不得与正文矛盾。

### 7.3 配套物料包

根据宣讲目标自动生成以下配套物料：

| 物料类型 | 适用目标 | 内容 | 输出格式 |
|----------|---------|------|---------|
| **独立演讲稿** | 全部 | 基于 PPT 内容生成的完整演讲稿（含开场白、过渡语、案例讲解、结束语），字数 ≈ 页数 × 300 字 | 飞书文档 / Word |
| **自测题与答案卡** | 合规考点类 | 从速查表和注意事项中抽取 10-20 道选择题/判断题，附标准答案和解析 | 飞书文档 / PDF |
| **签到反馈表** | 培训/宣贯类 | 联动 lark-base 生成多维表格，含签到、满意度评分、疑问收集 | 飞书多维表格 |
| **速查卡片** | 操作培训类 | 将关键操作步骤浓缩为 A4 可打印卡片（1 页 4 张），方便员工随身携带 | PPTX / PDF |

**配套物料生成方式**（脚本可按以下逻辑实现）：

```bash
# 演讲稿生成：读取 slide_plan.json → 按页面类型匹配备注模板 → 拼接完整演讲稿 → 输出 docx
# 自测题生成：读取 slide_plan.json → 从速查表/注意事项中抽取关键数字和字段 → 生成选择题/判断题 → 输出 docx
# 速查卡片生成：读取 slide_plan.json → 提取核心操作步骤 → 按A4版式排版4张卡片 → 输出 pptx
```

### 7.4 多格式导出

除飞书演示文稿外，支持导出为以下格式，兼容 WPS / Microsoft 365：

| 格式 | 适用场景 | 导出方式 |
|------|---------|---------|
| **PPTX**（本地可编辑） | 需要在 PowerPoint / WPS 中二次编辑 | 飞书「下载为 PPTX」或本地 generate.js 生成 |
| **PDF**（不可编辑，适合分发） | 仅浏览、打印、邮件附件 | 导出后转换为 PDF |
| **PNG/PDF 逐页图片** | 嵌入网页、微信预览 | 每页导出为高清图片 |

> **兼容性提示**：本地 PPTX 导出后，建议在 PowerPoint / WPS 中打开验证字体渲染（特别是特殊字体和中文排版），必要时替换为系统默认字体。

> 导出格式优先遵循 Step 0 中用户确认的「导出格式」选项。

## 关键原则

- **宣讲导向，非文档搬运** — 但操作培训类不得过度降级，操作说明、字段、注意事项必须保留在正文
- **信息密度按目标分级** — 宣贯降级，操作培训不降级，合规考点提炼
- **先大纲后生成** — Step 2 大纲必须用户确认（§2.9），避免方向偏差返工
- **事实校验优先** — 关键数字、法规引用、生效日期在交付前必须联网交叉验证，标注置信度；与源文档保真冲突时按 §2.8.4 仲裁规则处理
- **规划层强制** — 新建 PPT 必须先写 `slide_plan.json`，禁止跳过规划直接写 XML
- **品牌优先** — 若用户提供品牌指南，配色和字体严格遵循 VI 规范，冲突时以品牌为准
- **受众决定结构** — 同一份制度，面向新员工和管理层的 PPT 结构完全不同
- **素材兜底** — 真实截图缺失时优先 AI 生成素材，生成失败时用 XML-native 视觉兜底，不留空白框
- **回读验证** — 创建后必须回读全文 + 文本重叠 lint + **内容完整性校验**，不假设原子成功
- **源文档保真** — 提炼不等于篡改，制度条款、数字指标、生效日期、注意事项等强信息点必须与源文档一致
- **⚠️ 操作培训四要素** — 每个操作步骤页必须包含：操作说明 + 关键字段 + 注意事项 + 易错点
- **自然语言优先** — 用户修订请求优先接受自然语言输入，AI 自动解析意图和优先级
- **协作审阅** — 支持多人在线批注，按 P0/P1/P2 分级处理，冲突时以业务专家为准
- **模型无关（稳定输出）** — 尽量减少 skill 与工具功能对模型的依赖：排版坐标、配色、分页、连线、验证等机械动作一律固化到脚本与确定性规则中，模型只做语义判断（提炼、归类、文案），不参与像素/坐标/色值计算；切换模型后同一输入产出保持一致
- **工具先于模型** — 能用脚本/模板/规则完成的动作不依赖模型临场推理；模型输出不稳定时优先把该动作固化进工具
