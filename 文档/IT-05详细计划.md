# IT-05 详细计划与 DoR/DoD

## 1. 迭代目标

IT-05 的核心目标，是将当前项目从“已可运行、已有历史记录”提升为“可持续治理、可接续迭代、可标准化门禁”的状态。重点不是再扩展业务功能，而是固化项目管理范式和可追溯证据。

## 2. 迭代范围

### 2.1 目标范围

1. 固化 DevProjectTeamSkill 运行入口
2. 统一项目启动与收口的 checklist 流程
3. 统一风险、技术债和变更审计的状态更新机制
4. 明确下一轮可交付状态与接手条件
5. 确保项目状态可在新会话中无缝接续

### 2.2 非目标范围

- 不再进行大规模功能重构
- 不新增复杂业务流程能力
- 不在本轮中引入新的大规模依赖项

## 3. 工作分解

- 确认入口说明与当前项目一致
- 更新相关说明，确保新会话可直接使用

### 3.3 P1：风险/技术债治理

- 确认风险状态是否为“已评估/已缓解/持续监控”
- 确认技术债是否已具备优先级、责任人和偿还计划
- 针对治理风险补充闭环动作

### 3.4 P2：下一阶段可交付状态确认

- 明确下一轮可交付范围
- 确认 DoR/DoD
- 确保所有角色和交付物可追溯

## 4. DoR（进入迭代前置条件）

1. 已读取交接文档和当前状态基线
2. DevProjectTeamSkill 最新版本已启用
3. 关键台账已更新且具备可追溯性
4. 风险和技术债均已登记
5. 项目角色和责任边界已明确
6. 当前版本没有阻断性缺陷

## 5. DoD（完成标准）

1. 所有关键文档与台账已同步并可闭环
2. 风险/技术债状态已明晰且可追踪
3. 下一阶段工作范围、角色和交付物已确定
4. 启动 checklist 与门禁要求已落地
5. 新会话可从现有状态无缝接手
6. 无阻断性缺陷

## 6. 评审准则

### 6.1 范围评审

- 无未界定范围进入本迭代
- 工作目标与当前项目状态一致

### 6.2 质量评审

- 文档和台账一致性检查通过
- 关键结论可回溯到证据

### 6.3 风险评审

- 重大风险不超过可接受阈值
- 当前遗留项已登记并可跟踪

## 7. 预期产出

- 已更新的项目治理文档
- 完整的 IT-05 台账结论
- 具备可执行计划的下一轮迭代入口
- 可用于后续接手的项目状态基线
